# Vault — приватный мессенджер

Минималистичный мессенджер со сквозным шифрованием. Нет телефона, почты и имени: аккаунт — это пара
ключей, созданная на вашем устройстве, а ID — отпечаток этих ключей. Общение тоже только по ID.
Звонков нет — только личные сообщения и группы.

## Запуск

```bash
cd messenger
npm install
npm start          # http://localhost:8080
npm test           # тесты криптографии и протокола сервера
```

Переменные окружения: `PORT` (по умолчанию 8080), `DATA_DIR` (по умолчанию `./data`).

В браузере WebCrypto работает только в защищённом контексте: `localhost` или HTTPS. Для доступа из
сети разверните сервер за обратным прокси с TLS (nginx, Caddy) — WebSocket пойдёт по `wss://`.

## Разделы

- **Чаты** — личные сообщения. Контакт добавляется по ID; имя контакта видно только вам.
  Сообщения от незнакомых ID приходят с пометкой «Неизвестный» и кнопками «Добавить» / «Заблокировать».
- **Группы** — до 200 участников. Владелец добавляет, исключает и переименовывает; любой может выйти.
- **Настройки** — ваш ID, тема (авто / светлая / тёмная), автоблокировка, автоудаление сообщений,
  список заблокированных, резервная копия, блокировка и удаление аккаунта.

## Как устроена безопасность

| Что | Как |
| --- | --- |
| Регистрация | В браузере генерируются ключи ECDSA P-256 (подпись) и ECDH P-256 (шифрование). ID = первые 100 бит SHA-256 от обоих публичных ключей, 20 символов base32. |
| Вход на сервер | Без пароля на сервере: сервер присылает случайный nonce, клиент подписывает его ключом ECDSA. |
| Подмена ключей | Невозможна незаметно: клиент пересчитывает ID из полученных ключей и сверяет. Сверив ID с собеседником лично, вы исключаете «человека посередине». |
| Сообщения | На каждое сообщение — новый эфемерный ключ ECDH → HKDF-SHA256 → AES-256-GCM. Внутри — подпись отправителя ECDSA. |
| Что видит сервер | Только ID получателя и шифротекст. Отправитель спрятан внутри шифротекста, о группах сервер ничего не знает (рассылка идёт каждому участнику отдельно). После подтверждения доставки сервер удаляет сообщение; недоставленные удаляются через 30 дней. |
| Данные на устройстве | IndexedDB, всё зашифровано AES-256-GCM ключом из пароля (PBKDF2-SHA256, 600 000 итераций). Приватные ключи в памяти — неизвлекаемые `CryptoKey`. |
| Веб-защита | Строгий CSP без inline-скриптов, текст выводится только через `textContent`, `X-Frame-Options: DENY`, `no-referrer`, проверка Origin у WebSocket, ограничение частоты запросов и размера сообщений. |
| Группы | Изменения состава принимаются только от владельца и только с большим номером версии (защита от повторов). Сообщения от не-участников отбрасываются. |

Ограничения, о которых стоит знать:

- Нет полного протокола Double Ratchet (как в Signal): если украдут ключ получателя **и** перехваченный
  трафик, старые входящие сообщения можно расшифровать. Отправленные вами сообщения при утечке
  вашего ключа остаются защищены (эфемерные ключи).
- Пароль не восстанавливается. Потеряли пароль или устройство без резервной копии — потеряли аккаунт.
- Сервер видит IP-адреса подключений; для сокрытия используйте VPN или Tor.

## Структура

```
messenger/
├── server.js            сервер: статика + WebSocket-ретранслятор
├── public/
│   ├── index.html
│   ├── css/app.css      интерфейс; анимации только на transform/opacity (60 Гц)
│   └── js/
│       ├── crypto.js    вся криптография (общая для браузера и сервера)
│       ├── store.js     зашифрованное хранилище IndexedDB
│       ├── net.js       соединение с сервером
│       ├── core.js      контакты, группы, история, отправка/приём
│       └── app.js       интерфейс
└── test/                тесты (node --test)
```
